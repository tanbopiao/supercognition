## 1. 摘要与定位

自治系统最危险的不是进化得太慢，而是进化得**不受控**：随机变异、无门禁的规则改写、没有回滚的代际更替，任何一步都可能把系统推入不可逆的退化。本白皮书给出的答案是**六段闭环自治进化**：把"自主进化"拆成评估判定（EVAL）→ 记忆溯源（MEM）→ 变异推演（MUT）→ 验证收敛（VAL）→ 归档固化（ARC）→ 反馈循环（LOOP）六段，每段由一组职责单一的算子（共 24 枚）把守，任何变异分支都必须走完全程才能落为新一代基线。

设计目标一句话：**闭环自治进化——自主评估、推演、变异、验证、归档收敛，拒绝无约束随机突变。**

## 2. 设计定义

- **算子（Operator）**：进化管线上职责单一、可独立判定、可组合编排的最小治理单元。每枚算子有明确的输入、判定条件与触发阈值，判定结果只有"放行 / 拦截 / 升级人工"三种。
- **变异分支（Variant）**：一次候选变更（规则重组、架构微扰、蒸馏迁移、合成数据）从产生到收敛前所处的隔离状态。分支不接触线上基线，全部验证通过后才允许合入。
- **代际（Generation）**：基线的版本单位。每次锁档绑定时间戳、Merkle 根与确权标识，版本只增不覆盖（append-only），任何回退必须显式声明。

## 3. 总体架构：六段闭环

```
EVAL 评估判定 ──门控──▶ MEM 记忆溯源 ──▶ MUT 变异推演 ──▶ VAL 验证收敛
   ▲                                                        │
   │                                                        ▼
LOOP 反馈循环 ◀──调度回退/缺陷回流── ARC 归档固化 ◀──收敛池
```

六段构成一个循环（周行不殆）：评估放行才启动进化；记忆提供经验基底；变异做多分支并行探索；验证把分支收敛到最优；归档把胜者锁成新代际；反馈把真实表现带回下一轮评估。任何一段不满足条件，整轮进化就地终止或升级人工，**不存在绕行通道**。

## 4. 二十四算子明细

### P0 评估判定（EVAL · 进化启动门控）

| 算子 | 名称 | 定义 | 触发阈值 |
| --- | --- | --- | --- |
| EVAL-01 | 稳态得分 | 多维指标聚合：推理一致性、召回精度、任务通过率、漂移率、资源开销 | ≥80 分允许自主进化；＜80 暂停迭代推演 |
| EVAL-02 | 真值偏差 | 比对 Merkle 账本基准真值，计算输出偏离度，标记冲突样本 | 偏差超阈值生成冲突报告，推送人工审批 |
| EVAL-03 | 价值收益 | 计算能力增益/算力消耗比，筛选高收益进化方向，淘汰低效分支 | 收益为负直接丢弃该变异分支 |
| EVAL-04 | 安全边界 | 扫描变异后规则是否触碰元宪法红线，触发熔断阻断 | 命中红线→冻结分支、日志入冷存储 |

### P1 记忆溯源（MEM · 经验基底）

| 算子 | 名称 | 定义 |
| --- | --- | --- |
| MEM-01 | 双向同步网关 | 拉取 converge 基线，对齐全域记忆库 |
| MEM-02 | 快照指纹 | 对当前权重、规则集、Prompt 内核生成 SHA256，写入哈希账本 |
| MEM-03 | 冷仓检索 | 调取历史代际归档版本，做回溯对照、消融比对 |
| MEM-04 | 遗忘修剪 | 剔除冗余、低价值样本，保留高冲突、高增益核心样本 |

### P2 变异推演（MUT · 进化探索）

| 算子 | 名称 | 定义 |
| --- | --- | --- |
| MUT-01 | 架构微扰 | 调整子模块连接权重、路由策略、注意力偏置，小步探索 |
| MUT-02 | 蒸馏迁移 | 从高分分支做知识蒸馏，将稳态能力迁移至目标实例 |
| MUT-03 | 规则重组 | 重组内部决策公理、分支判断逻辑，生成候选规则集 |
| MUT-04 | 合成数据生成 | 基于世界模型生成测试样本，构建闭环测试集，不依赖外部投喂 |
| MUT-05 | 异构路由 | 内核调度，在候选变异分支间分配异构算力资源并行推演 |

### P3 验证收敛（VAL · 校验过滤）

| 算子 | 名称 | 定义 |
| --- | --- | --- |
| VAL-01 | 对照复测 | 基线版本 vs 变异版本，相同测试集批量复测 |
| VAL-02 | 冲突消解 | 三级消解：元法则→元公理→人工审批，解决输出分歧 |
| VAL-03 | 防漂移 | 约束基础能力不丢失，禁止进化后原有能力退化 |
| VAL-04 | 分支剪枝 | 多候选分支横向对比，仅保留稳态最优分支进入收敛池 |

### P4 归档固化（ARC · 代际锁档）

| 算子 | 名称 | 定义 |
| --- | --- | --- |
| ARC-01 | 代际版本 | 版本号自增，绑定时间戳、Merkle 根、确权标识 |
| ARC-02 | 双副本落盘 | 文本内核本地磁盘 + 云端冷存储双副本写入 |
| ARC-03 | 只读锁档 | 固化资产设置只读权限（444）；修改必须人工审批解锁 |
| ARC-04 | 全域广播 | 向分布式节点推送新版本基线，同步 converge 分支真值 |

### P5 反馈循环（LOOP · 持续闭环）

| 算子 | 名称 | 定义 |
| --- | --- | --- |
| LOOP-01 | 环境交互采样 | 从任务执行日志采集真实反馈样本，回流评估池 |
| LOOP-02 | 缺陷标记 | 持续标记失败案例，优先作为下一轮进化推演素材 |
| LOOP-03 | 调度回退 | 新版本稳态崩坏时，一键回退至上一锁档代际快照 |

## 5. 一轮进化的生命周期

1. **门控**：EVAL-01 汇总多维指标出稳态得分；≥80 放行，EVAL-02 对账真值偏差，EVAL-04 掂量收益，EVAL-03 扫安全红线——四关全过才立项。
2. **立基**：MEM-01 拉取 converge 基线，MEM-02 对当前权重/规则/内核生成快照指纹入账，MEM-03 可调冷仓对照历史代际。
3. **探索**：MUT-01~04 产生多个候选分支（微扰、蒸馏、重组、合成），MUT-05 在候选分支间分配异构算力并行推演。
4. **收敛**：VAL-01 以同一测试集做基线-变异批量复测；VAL-02 消解冲突；VAL-03 守住基础能力底线；VAL-04 剪枝只留稳态最优。
5. **锁档**：ARC-01 出新代际版本（时间戳+Merkle根+确权），ARC-02 双副本落盘，ARC-03 只读固化，ARC-04 全域广播。
6. **回流**：LOOP-01 采集真实执行反馈，LOOP-02 把失败案例升格为下轮素材；若新代际稳态崩坏，LOOP-03 一键回退上一锁档。

## 6. 公理约束（三条，违反即熔断）

1. 所有变异分支，**不可脱离已确权账本真值单独演化**；
2. 高风险架构改动、公理修改分支，**强制阻断自主进化，必须人工审批放行**；
3. 资源调度优先零成本 API、本地算力，**成本收益为负分支直接淘汰**。

## 7. 工程实例化现状（真实落地）

- **哈希账本与归档体系（MEM/ARC 段实例）**：记忆资产脱敏哈希入账、Merkle 快照、热读/温层/冷层三层归档、444 只读固化、异常熔断告警、冷备推送待确认后启用——ARC-02/03 与 MEM-02 的完整工程实现，全链路可审计。
- **昆仑洞天进化轮（MUT/VAL 段实例）**：每小时自动执行种子投喂六步闭环（选种、美学四层门禁、构建、部署、验证、上报），资产随法则方位持续生长；全量瘦身实测三件资产体积降 56%，全程只增不覆盖。
- **视觉质检哨（VAL-01/03 实例）**：真浏览器采集 + 视觉判读四关（完整性/空间/美学/功能）+ 基准帧差分；第 0 关几何流形体检已插入构建校验管线，非流形与缠绕异常即拦截。
- **AxiomGate 裁决内核（VAL-02 实例）**：三级消解（规则→公理→人工）的工程化裁决引擎，开源可查。
- **联邦记忆网关（MEM 段实例）**：单一真相源 + 锚定检索 + 五域联邦读取面，为本清单记忆段的运行基座。
- **双推演门（EVAL 段实例）**：对外动作前的双推演评审，对应"高风险分支强制人工放行"公理。

## 8. 边界与诚实披露

- 24 枚算子为治理层定义；各实例的覆盖深度不同，上文"实例化现状"仅列已落地部分，不宣称全量覆盖。
- EVAL-01 的多维权重、EVAL-02 的偏差阈值属调参空间，随运行数据持续校准，本白皮书不锁定具体数值。
- 调度回退依赖冷层母体可用性；冷存储通道故障时回退降级为人工路径。
- 本白皮书描述的是治理框架与已验证实例，不构成对任何第三方系统适用性的承诺。

- 中期：六段闭环与全域作品自动进化打通，任一阵地的缺口发现即触发本地生长。
